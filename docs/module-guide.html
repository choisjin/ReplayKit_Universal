StartLogging은 포트가 이미 열려 있으면 재open하지 않고 캡처 세션만 시작하므로, connect 시 설정이 초기화되는 장비도 안전하게 사용할 수 있습니다. **⚠️ 사용법: StartLogging과 StopLogging은 한 셋트로 사용하세요.** - StartLogging만 호출하고 StopLogging을 누락하면 메모리 버퍼가 파일로 저장되지 않습니다. - StopLogging은 캡처 세션을 종료하지만 **포트 연결은 그대로 유지**합니다. 포트를 닫고 싶다면 Device 탭에서 Disconnect 하세요. - 시나리오가 비정상 종료되어도 cleanup이 Disconnect 시 미저장 로그를 자동 저장합니다. 표준 사용 패턴: 1) StartLogging() ← 시나리오 첫 스텝 (캡처 시작, 포트는 Device 탭에서 미리 Connect) 2) SendCommand / SendCommand_*_on_keyword ... ← 중간 스텝들 3) StopLogging() ← 시나리오 마지막 스텝 (로그 파일 저장 + 캡처 종료, 포트는 유지)

DLT 로깅 — DLT 데몬에 TCP 직접 연결하여 로그를 캡처·저장하고 키워드 PASS/FAIL 판정하는 모듈 (GUI 불필요)

timeout: 총 대기 시간 (초, 기본 60)
max_retries: 최대 재시도 횟수 (기본 5). 간격 = timeout ÷ max_retries

timeout: 총 확인 시간 (초, 기본 60)
max_retries: 최대 확인 횟수 (기본 5). 간격 = timeout ÷ max_retries
